# Тестовый прогон пайплайна оценки материалов — инструкция для модели

Ты работаешь в изолированной копии проекта. Здесь свои скрипты, промты, справочники
(`_канон/`) и исходники (`ИСХОДНИКИ/`). Другие копии этой папки не видят.

## Вызов модели по API

Если задан ключ в `api.env` или `.env`, `прогон.py` сам вызывает модель
через `POST {API_BASE}/v1/messages` (Anthropic Messages, router.cheap).
По умолчанию: `https://direct.router-cheap.com`, модель `claude-opus-5`.
Температуру не задаём. Effort — у каждого модельного шага в `шаги.py`
(П1/П1т/И* — medium, П2/П3/П2т/П5/У1 — high, П4 — xhigh).
`API_EFFORT` в `api.env` перекрывает все шаги, если задан.
Ключ в git и в чат не класть.
Проверка: `python3 _скрипты/модель.py`.
Ручной режим: `python3 _скрипты/прогон.py --без-api <исходник> материалы/<папка>`.

## Что делать

Для каждого из трёх материалов — цикл, пока прогон не скажет «пройдено до конца»:

Весь корпус: `python3 _скрипты/прогон_корпус.py` (все PDF из `ИСХОДНИКИ/`).
Материалы идут по 10 одновременно; вывод каждого печатается целиком, когда тот
закончился. По одному, как раньше: `--потоков 1`.
С автоправкой цитат и повторами: `python3 _скрипты/довести.py --все`.

Один материал:

```
python3 _скрипты/прогон.py "ЧД/Я помогала управлять Lululemon ред.pdf"   материалы/ЧД_Я_помогала_управлять_Lululemon_ред
python3 _скрипты/прогон.py "ПОИСК/01_Online_Review_Analysis.pdf"         материалы/ПОИСК_01_Online_Review_Analysis
python3 _скрипты/прогон.py "ЧД/Человекоцентричный_Автономный_Банк.pdf"   материалы/ЧД_Человекоцентричный_Автономный_Банк
```

1. Запусти прогон. Скрипты отработают сами; там, где нужна модель, прогон
   остановится с кодом 2 и напишет: промт, вход, куда положить ответ. Всё
   вместе, для одного копирования, лежит в `материалы/<папка>/_вызов.md`:
   сначала промт, потом файлы входа, в конце — адрес ответа.
2. Прочитай `_вызов.md` и ответь **строго по схеме из раздела «Выход» промта**:
   один JSON, без текста вокруг, без markdown-обёртки. Если во входе сказано
   «по строке за вызов» — каждая строка входного файла обрабатывается отдельно, в
   том же порядке; ответы — по строке в `.jsonl`, либо объектами в список `темы`
   одного объекта `{"темы": [...]}` для `.json` (как написано в `_вызов.md`).
3. Положи ответ в указанный файл и запусти прогон снова. Он проверит ответ по
   контракту: код 4 — ответ не по схеме, прогон напишет, что именно не так;
   исправь **ответ**, не промт. Код 4 ставится и когда ответ не про этот вход
   (чужие цитаты, чужие блоки, чужие сюжеты, не по всем кандидатам, адрес блока
   не из своего фрагмента) — тоже исправь ответ. Код 1 — упал скрипт или нет
   входа: остановись и сообщи человеку.
4. Повторяй, пока прогон не выведет `✓ пройдено до конца`. Потом — следующий
   материал.

По всем трём — `python3 _скрипты/сводная.py материалы` (таблица по всем).

## Чего не делать

- Не редактировать скрипты (`_скрипты/`), промты (`_промты/`), справочники
  (`_канон/`), исходники и файлы, которые пишут скрипты. Единственное, что ты
  пишешь руками, — файлы ответов, названные в `_вызов.md`.
- Не пропускать остановки и не выдумывать ответ без входа: если `_вызов.md`
  пуст или входа нет — это сбой, скажи об этом человеку, не продолжай.
- Не заводить строки справочников руками: И2 и И3 — это тоже ответы модели по
  промту, скрипт запишет их сам.
- Шаги И1, И2, И3 разрешают поиск в интернете; остальным промтам поиск не нужен
  и запрещён — всё, что можно цитировать, лежит во входе.
- Не подменять модель: этот корень — для одной модели от начала до конца.

## Если что-то упало

Код 1 с текстом от скрипта — прочитай текст, обычно он называет файл и причину.
Если причина не в ответе (нет библиотеки, нет исходника) — остановись и сообщи
человеку, что именно написал прогон. `python3 _скрипты/окружение.py` проверяет
окружение (нужны pymupdf, python-docx, openpyxl — `pip install -r requirements.txt`).

## Как устроена оценка

Порядок шагов печатает `python3 _скрипты/шаги.py`. Модельных вызовов одиннадцать,
по одному промту на каждый; чем занят каждый — в шапке промта. Опорные точки:

- Каждый фрагмент текста разбирается дважды, по двум назначениям. **П1** читает
  фрагмент без канона и выписывает тезисы, кейсы, термины, цифры, адресацию,
  инструменты и опоры под практику — свойства текста; от канона этот ответ не
  зависит, и жанр документа (П2) опирается на него. **П1т** читает
  тот же фрагмент с каноном тем в руках и называет, какие темы здесь обсуждаются,
  на каких отрезках, и какие блоки — утверждения о способе действия — стоят
  внутри каждой темы. Это единственное место, где тема привязывается к тексту.
- Объём темы считается по её фрагментам — непрерывным диапазонам отрезков, где
  тема обсуждается, — а не по блокам. Балл A берётся из самого длинного
  непрерывного куска по теме; блоки определяют содержание темы и её сюжеты.
  Фрагмент без блоков законен: текст про тему есть, способа действия в нём нет.
- **П2** судит о документе целиком: о чём он, жанр, зависимость от продукта,
  отрасль, адресат, ограничения. Сюжетов в этом ответе нет.
- **П3** применяет исключения тем к материалу целиком; тему в тексте она не ищет.
- **П2т** раскладывает блоки одной темы-кандидата на сюжеты — по строке на
  кандидата. Заготовка для аналитика собирается из фрагментов темы и её сюжетов.
- П4, П5, У1, И1–И3 — строгая проверка, скоринг, уровни и опознание источника.
- Последний шаг прогона — выгрузка: у материала хотя бы с одной принятой (✅)
  темой скрипт собирает папку `выгрузка/<папка>/` для аналитика — паспорт,
  заготовки, решение, текст, копию оригинала. У остальных пишется только
  `выгружено.json` с причиной. Папку `выгрузка/` не редактировать.
